# موجة EQ — صدق حالة الولاء على طلب الصالة + خرائط موافقة مزدوجة

**التاريخ:** 28 يوليو 2026

## الهدف

`getOrder` كان يعيد نقاط الولاء دون `customerEnabled`/`redeemEnabled`، فواجهة الصالة تعرض نقاطاً وحقل استبدال حتى عند تعطيل البرنامج. أيضاً أخطاء الموافقة المزدوجة الشائعة بلا خرائط عربية.

## التغييرات

| ملف | ماذا |
|-----|------|
| `resto.service.ts` | إثراء `loyalty` من `getContactPoints` في `getOrder` |
| `resto/page.tsx` · `api.ts` | إخفاء الاستبدال + نص صادق عند تعطيل النقاط |
| `utils.ts` | خرائط عربية لأخطاء Dual Control / OTP |

## سلوك

- ضيف مرتبط + ولاء معطّل → «ضيف مرتبط — نقاط الولاء غير مفعّلة» بلا حقل استبدال
- OTP/طلب موافقة فاشل → رسالة عربية مفهومة عند التعرّف

## التالي

Cloudflare / Sentry / OTP يدوياً.
