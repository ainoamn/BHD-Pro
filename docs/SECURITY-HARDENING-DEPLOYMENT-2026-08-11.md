# دليل نشر حزمة التقوية — 2026-08-11

## الهدف

هذه الحزمة تعالج مخاطر P0/P1 في التدقيق، الصلاحيات، XSS/SSRF/CSRF، المدفوعات، كلمات المرور، مفاتيح API، التشفير، عزل الشركات، الحسابات المالية، المرفقات، CI وDocker. النشر يجب أن يكون تدريجياً مع نسخة احتياطية واختبار استعادة.

## ترتيب النشر الإلزامي

1. أنشئ نسخة احتياطية متسقة واختبر استعادتها في قاعدة منفصلة.
2. جهز أسراراً مستقلة: `JWT_SECRET` و`JWT_REFRESH_SECRET` و`PAYMENT_SECRETS_KEY` و`TOTP_SECRETS_KEY`، كل واحد عشوائي مختلف بطول 32 حرفاً على الأقل.
3. اضبط `*_KEY_ID` واترك `*_PREVIOUS_KEYS={}` لأول نشر. لا تحذف مفتاحاً قديماً قبل إعادة تشفير كل السجلات التي تستخدمه.
4. جهز S3 خاصاً للمرفقات، تشفير SSE-S3 أو KMS، وRedis بكلمة مرور URL-safe.
5. انشر صورة التطبيق، ثم شغّل مرة واحدة:

   ```bash
   npx prisma migrate deploy --schema src/prisma/schema.prisma
   ```

6. شغّل Backend بعد نجاح الهجرة، ثم Frontend. لا تستخدم `prisma migrate deploy` في أمر بدء كل replica.
7. نفّذ smoke tests لحسابين في شركتين مختلفتين، مستخدم Viewer، مفتاح API للقراءة فقط، دفع تجريبي، وإعادة تعيين كلمة مرور.
8. راقب 401/403/409/5xx، فشل webhooks، زمن قاعدة البيانات، وامتلاء Redis لمدة 30 دقيقة قبل زيادة الحركة.

## ما تفعله الهجرة

- تضيف `payments.idempotency_key` مع قيد uniqueness.
- تضيف رموز استعادة كلمة المرور مجزأة ومنتهية الصلاحية.
- تضيف جدول التسلسلات الذرية لأرقام المستندات.
- تضيف scopes/expiry/IP لمفاتيح API. المفاتيح القديمة تُرحّل إلى read+write لجميع الوحدات حفاظاً على التوافق؛ المفاتيح الجديدة read-only افتراضياً.

## تدوير مفاتيح التشفير

مثال دفع:

1. انقل القيمة القديمة إلى `PAYMENT_SECRETS_PREVIOUS_KEYS={"pay-2026-01":"OLD_VALUE"}`.
2. اضبط `PAYMENT_SECRETS_KEY_ID=pay-2026-02` و`PAYMENT_SECRETS_KEY=NEW_VALUE`.
3. أعد التشغيل؛ القراءة تدعم القديم والجديد، والكتابة تستخدم الجديد.
4. نفّذ مهمة إعادة تشفير مسيطر عليها مع عدّ للسجلات والتحقق قبل/بعد.
5. لا تحذف المفتاح القديم حتى تصبح سجلات الإصدار القديم صفراً وتنجح نسخة الاستعادة.

كرر الإجراء مستقلاً لـTOTP. لا تستخدم مفتاح الدفع لـTOTP في الإنتاج.

## خطة rollback

- أوقف الحركة الكتابية قبل الرجوع إذا استُخدمت الحقول الجديدة.
- أعد صورة التطبيق السابقة فقط إذا بقيت الهجرة متوافقة؛ لا تحذف الأعمدة أثناء حادث حي.
- عند فشل الهجرة، أوقف release job، احتفظ بسجل SQL، واستعد النسخة فقط إذا أصبحت قاعدة البيانات غير متسقة.
- قيود uniqueness الخاصة بالدفع والترقيم ضوابط سلامة؛ لا تُسقطها لحل تعارض، بل أصلح البيانات المكررة يدوياً بعد حفظها.
