## 1) ملخص تنفيذي

| المنتج | المسار | الحالة |

## 2) ما أنجزته المحاسبة

- فواتير مبيعات/مشتريات، عروض، إشعارات دائنة/مدينة، أوامر شراء، فواتير مجدولة
- تحصيل ودفعات، عكس التحصيل، تراجع عن الإرسال، إلغاء فاتورة
- دليل حسابات، قيود يومية، ترحيل GL تلقائي عند الإرسال والتحصيل
- **ترحيل GL للرواتب والمطالبات** (استحقاق عند الاعتماد + صرف عند الدفع مع تحديث رصيد البنك)
- **التزامات دورية** (إيجار/قروض…) مع إيقاف وتأجيل وتشغيل يومي
- **مرفقات مستندات** + **تنبيهات إدارة** للمراجع المكررة والمعاملات المتشابهة
- مخزون ومنتجات، مستودعات، جرد، تحويل بين مستودعات، أرصدة `WarehouseStock`
- تقارير (مبيعات، مشتريات، VAT، مخزون…) + تصدير PDF/Excel/CSV
- فترات محاسبية (إقفال/فتح)، معدلات ضريبية، بنوك وتسوية
- أصول ثابتة، رواتب، مراكز تكلفة، فروع، مشاريع
- حماية مزدوجة (maker-checker) على إلغاء فاتورة وعكس دفعات وصرف رواتب/مطالبات والتحويل البنكي الداخلي
- تسوية بنكية: اقتراحات مطابقة من GL/الدفعات على `/bank-reconciliation` + تطبيق التسوية
- ربط اختياري مع الكاشير (`pos_*` على الشركة + مفتاح تقني)
- PWA خفيف (manifest + service worker) + اختصارات كاشير/محاسبة
- Onboarding checklist ومؤشرات لوحة أذكى (يوليو 2026)
- أكواد خصم الاشتراك مربوطة بمسار الدفع (`promoCode` + عروض `PlanOffer`)
- GeoIP للزيارات عبر ترويسات Cloudflare/Vercel
- Keep-warm لـ Render عبر GitHub Actions كل 10 دقائق
- إخفاء واجهة AI التجريبية من القائمة الجانبية

## 4) فجوات متبقية (موثّقة)

| فجوة | ملاحظة |
|------|--------|
| WhatsApp OTP إنتاجي بالكامل | هيكل موجود؛ يحتاج أسرار/مزوّد جاهز |
| إيصالات بريد SMTP / SMS (Twilio) | التالي — اليوم: واتساب خادم تلقائي + mailto يدوي من الجهاز |
| أوفلاين كامل للكتالوج/المخزون | مزامنة `/pos/catalog/sync` + كاش IndexedDB حسب المستودع |
| ائتمان متجر / استرداد أوسع | منجز — محفظة + ترحيل GL عبر `2130` / `STORE_CREDIT` |
| دفع متعدد (split tender) على عملية واحدة | منجز — `payments[]` + واجهة نقد/بطاقة |
| ملاحظات سلة معلّقة + بقشيش على البيع | منجز — `pos_drafts.notes` + `tipAmount` |
| موافقة مزدوجة لإخراج نقد كبير | مؤجّل — `SHIFT_CASH_OUT` اختياري |
| Web Bluetooth حراري موثوق لكل الطابعات | مسار تجريبي؛ Serial هو الأساس |
| OTA / فاتورة إلكترونية رسمية كاملة | إعدادات موجودة؛ التكامل التشغيلي ناقص |
| AI حقيقي | مخفي من القائمة — ليس إنتاجياً |
| استقرار DNS للدومين على بعض الشبكات | راجع قسم النشر |
| دفع NFC/محافظ عبر شركاء بوابة | مخطّط (ليس شارة الموافقة) |
| Capacitor / غلاف أصلي | مخطّط إن تجاوزت حدود PWA |

## 5) خطة مستقبلية — مراحل A / B / C

### المرحلة A — تثبيت التشغيل (قصير)
- تطبيق migrations الجديدة على الإنتاج (`approval_requests`, `cashier_shifts_otp`, `pos_cash_movement_journal`, …)
- اختبار الكاميرا على Android/iOS + موافقات المدير من جهاز ثانٍ
- استقرار الدومين (Cloudflare / A record) وتقليل cold start على Render

### المرحلة B — نضج الكاشير والأمان (متوسط)
- ترحيل ائتمان المتجر إلى قيود GL/AR كاملة (حساب `2130` + `PaymentMethod.STORE_CREDIT`) — منجز يوليو 2026
- ترحيل إدخال/إخراج نقد الصندوق إلى GL — منجز يوليو 2026
- طباعة BLE حرارية موثوقة عبر بائعين محددين / جسر محلي
- مراقبة إشعارات واتساب للموافقات في الإنتاج
- موافقة مزدوجة اختيارية لإخراج نقد فوق حد

### المرحلة C — توسّع وتكامل (لاحق)
- أوفلاين-first مع مزامنة كتالوج/مخزون كاملة
- دفع NFC/محافظ عبر شركاء بوابة
- OTA e-invoice كامل + مراقبة
- تطبيقات جوال/تابلت أصيلة أو Capacitor فوق نفس `/pos`
- AI تشغيلي (تنبيهات مخزون، اقتراحات تسعير) مع إشراف بشري
